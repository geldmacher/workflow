# Review Schema 5

Fresh read-only Review binds Root/Evidence without upgrading proof. Inspect Authority, paths, failures, Checks. Inline first; fixed `replan|clarify` stops. Targeted adds one specialist; certified, Hard-Trigger, high/critical, or cross-cutting work needs delivery+risk (material design).

Resolve explicit Root, active Plan, unique Run. Task artifacts beat cache/roots failure. Invalid, conflicting, or ambiguous context grants nothing.

Root-boundary requires typed irrecoverable post-mutation recovery: `baseline-unavailable-after-mutation|out-of-authority-changes|workspace-ambiguous-after-mutation|root-binding-lost-after-mutation`. Its short-lived protected host record binds receipt ID/time/error, exact Root/current-snapshot hashes and canonical paths. Fixed: `latest_evidence_id:null`, `insufficient-evidence/blocked/inline/replan`, empty coverage, `[inline]`, no Finding/correction/acceptance/achievement/retry/Learning. Only the unique trusted current tip sources linear replan; missing trust, portable/rootless validation, transport gaps, or stale state fail closed.

Verified completes; provisional needs acceptance; failure blocks. In-Root gaps offer correction approval; changed boundaries replan; uncertainty clarify/retry. Two no-progress corrections require clarify/replan.

Reviewer, not `work-explainer`: order `What was achieved`, `What this means`, `Verification and limits`, `Technical traceability`. The first three stand alone without implementation history or code knowledge; the last separates executor claims from independently inspected evidence. Final is achieved-only; otherwise preliminary plus the [guide](https://github.com/geldmacher/workflow/blob/main/docs/manual-workflow.md#review-results-and-next-actions).
