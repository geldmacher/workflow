# Shared working agreement

Humans commission phases separately or expressly commission [Auto-Work](../skills/auto-work/SKILL.md); only that sequence authorizes transitions. Learning needs its own assignment.

When you receive a `BEGIN PLAN AND BOUNDARIES` block, check its three fields before any repository access: plan with criteria, working directory with read roots, and write scope with exclusions. If the block is an exact reference, read that reference first. If a field is blank, read only the explicitly named rules at the supplied working directory, then return the block unchanged and name the missing fields; do not look up or fill in values. Read the rules before `pwd`, `ls`, Glob, AGENTS.md, or other repository access. Auto-Work children follow the [handoff rules](../skills/auto-work/SKILL.md#handoffs) and never coordinate.

Follow the applicable plan: the human-approved plan in standalone work and Light, or the plan prepared within a commissioned Dark goal. Material changes to the goal, acceptance, authority, or consequential decisions need a human decision. Preserve approvals; routine technical choices belong to the executor.

Align consequential choices with the north star. When direction is missing or the human explicitly changes it, use [project readiness](project-readiness.md) and carry those decisions and pending updates through handoffs.

Keep plans, reports, and one learning collection in the native task. Write reports or logs to the repository only when assigned. Handoffs carry the plan, assignment, state, evidence, decisions and setup offers, next action, and learning changes with a reference; supply the full text when the receiver cannot reach a reference. Never invent approvals or history.

For new or inherited learning, follow the [learning guidance](learning-work.md). Keep all open candidates and their evidence accessible. A status report does not renew offers.

Preserve unrelated work. Host permissions govern; Review is repository-read-only. Git writes, installation, production access, delivery, publication, and learning need explicit authorization. Auto-Work includes delivery only when it was commissioned.

Reuse applicable instructions and current proof; load conditional detail when its condition applies. Further work needs a concrete unresolved question. Failed necessary checks prevent a success claim; missing proof and changed states stay visible.

Reply in the user's language with the result first and evidence beside each claim. Scale detail to the task instead of using fixed formats. End with the outcome and next action. An achieved goal needs no further phase; Auto-Work reports repository outcome, human acceptance, and delivery separately.
