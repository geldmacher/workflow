# Manual attestation

Typed closeout only. Schema-5 artifacts built by the deterministic closeout kernel are authoritative. Free-form `[workflow-closeout-v1]`, top-level delivery fields, `content[].text` JSON, or prose `de-*` scanning never grant authority. Host adapters may unwrap known MCP transport envelopes before calling the kernel.

Cursor final todos: short `[workflow-model-inherit-v1] …` text plus `workflow_attestation: { schema: 1, kind: plan-closeout, action: delivery-closeout }`. Codex `## Final implementation step`: one unindented ` ```yaml workflow-attestation ` plan-closeout fence with the same action. Legacy `action: workflow_closeout` remains accepted. Reject indented, tilde, commented, negated, duplicate, or unknown-field forms.

Native implementation, correction, or review recovery supplies exactly one unindented `yaml workflow-attestation` block with `schema: 1`, `kind: closeout-input`, the exact phase, `root_plan_id`, non-negative `strategy_revision`, structured `check_evidence`, and a concise `summary`. `changed_paths` may be omitted; when retained by an older caller it is only a normalized compatibility hint and grants no Authority. Unknown fields and caller-supplied Evidence identity, hashes, topology, aggregate grade, mode, status, or path scope fail closed. Before implementation/correction mutation, the host revalidates independently captured exact Root bytes, captures the repository baseline, and denies directly observable protected, approval-required, or out-of-authority targets. Root or baseline failure denies the mutation. The host derives the final snapshot and complete changed-path inventory, enforces Root path authority against that inventory, calls the shared builder, and persists exact Evidence. Native success requires no delivery-report.

`workflow_closeout` `structuredContent` must include `delivery_evidence_id`, exact `artifact` bytes, lowercase SHA-256 `artifact_hash`, `root_plan_id`, `root_content_hash`, `status`, `handoff_persisted`, and lineage fields (`subject_id`, `source_review_id`, `predecessor_evidence_id`) that match the artifact. Hosts bind an independently captured active Root ID and exact Root-content hash of the raw UTF-8 Root artifact bytes (`rootContentHash`); semantic normalization and `rootPlanFingerprint` may check presentation/preflight sameness but must not authorize closeout. Hosts must supply an explicit `expectedLineage` object; omission of lineage or Root hash fails closed. Same-ID Evidence with a different Root-content hash fails closed, including CRLF versus LF byte variants. Full-root closeout requires `subject_id` equal to the Root with null review/predecessor tips; correction closeout requires the complete review tip tuple from explicit chain artifacts.

The optional MCP path still requires exactly one delivery-report fence with the recorded `de-*` ID. Persisted MCP Evidence must not appear in the completion message; unpersisted MCP Evidence must appear exactly once as a bounded attachment. Both adapters invalidate recorded native or MCP closeout after later mutation, including child-agent mutation. Cursor permits the semantic delivery-closeout todo to complete pending the final native report, while the legacy MCP todo retains its pre-completion gate. Missing native Evidence produces one bounded recovery instruction, never an invented `de-*` report.

Cursor arms baseline capture and Stop recovery only when the current turn has both a conversation-bound Root and an explicit Manual implementation, correction, or review phase. Ordinary Ask-mode Shell/Task use, a Root from another conversation, or an older Root in the same conversation without a current Workflow turn must not create closeout-required state. An explicit closeout transport without a bound Root reports that no Root exists for the current task and emits no Evidence-recovery request.

Fresh review is read-only. When exact Evidence is missing, the reviewer may gather observations once and submit `phase: review-recovery`. The host first hydrates an identical persisted tip, otherwise builds Evidence, then continues the same review once with the exact chain. Without a pre-mutation baseline, only the complete unambiguous current dirty set wholly within Root authority may produce provisional Evidence; caller path hints never narrow or widen it. Verified observations are capped at `supported`, and a known failed Check stays failed. If recovery proves that baseline, Root binding, workspace identity, or path authority was irrecoverably lost after mutation, the native host records a short-lived protected receipt bound to the exact Root and current repository snapshot. Only a Review carrying that exact receipt may use the Schema-5 root-boundary variant. That Review has no Evidence and can authorize only a separately approved replan; portable/rootless or stale receipts authorize nothing.

Codex retains exact Schema-5 Root, generated Evidence, and emitted Review bytes in session/task state under the exact Root-content hash. A subsequent correction uses that task-local chain automatically; `workflow_artifact_context` may enrich it and `workflow_artifact_record` may transport it, but neither is required for the native happy path. Same-ID byte variants, different Root hashes, missing Source Review, stale predecessor Evidence, and conflicting correction lineage remain explicit fail-closed errors in the Stop response.

Shared adversarial lifecycle matrices must drive real kernel/Cursor/Codex/bundle adapter behavior for every applicable case. Enumerating case IDs or asserting a static expected outcome without invoking the host adapter is not proof. Before correction closeout, compare the normalized authorized dirty path set under Root authority with Evidence `changed_paths` and fail closed on omission or extras.

Unfinished-content detection matches explicit placeholder markup and uppercase `TBD`/`TODO`/`UNKNOWN` only; ordinary planning prose such as title-case Todo metadata must not fail closed.
