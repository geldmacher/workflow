# Manual attestation

Typed closeout only. Schema-5 artifacts built by the deterministic closeout kernel are authoritative. Free-form `[workflow-closeout-v1]`, top-level delivery fields, `content[].text` JSON, or prose `de-*` scanning never grant authority. Host adapters may unwrap known MCP transport envelopes before calling the kernel.

Cursor final todos: short `[workflow-model-inherit-v1] …` text plus `workflow_attestation: { schema: 1, kind: plan-closeout, action: delivery-closeout }`. Codex `## Final implementation step`: one unindented ` ```yaml workflow-attestation ` plan-closeout fence with the same action. Legacy `action: workflow_closeout` remains accepted. Reject indented, tilde, commented, negated, duplicate, or unknown-field forms.

The normal Cursor lifecycle invokes the existing closeout builder internally and commits exact Evidence before its final user response. A host that cannot complete that internal path may supply exactly one unindented `yaml workflow-attestation` fallback block with `schema: 1`, `kind: closeout-input`, the exact phase, `root_plan_id`, non-negative `strategy_revision`, structured `check_evidence`, and a concise `summary`. `changed_paths` may be omitted; when retained by an older caller it is only a normalized compatibility hint and grants no Authority. Unknown fields and caller-supplied Evidence identity, hashes, topology, aggregate grade, mode, status, or path scope fail closed. Before implementation/correction mutation, the host revalidates independently captured exact Root bytes, captures the repository baseline, and denies directly observable protected, approval-required, or out-of-authority targets. Root or baseline failure denies the mutation. The host derives the final snapshot and complete changed-path inventory, enforces Root path authority against that inventory, calls the shared builder, and persists exact Evidence. Native success requires no delivery-report.

`workflow_closeout` `structuredContent` must include `delivery_evidence_id`, exact `artifact` bytes, lowercase SHA-256 `artifact_hash`, `root_plan_id`, `root_content_hash`, `status`, `handoff_persisted`, and lineage fields (`subject_id`, `source_review_id`, `predecessor_evidence_id`) that match the artifact. Hosts bind an independently captured active Root ID and exact Root-content hash of the raw UTF-8 Root artifact bytes (`rootContentHash`); semantic normalization and `rootPlanFingerprint` may check presentation/preflight sameness but must not authorize closeout. Hosts must supply an explicit `expectedLineage` object; omission of lineage or Root hash fails closed. Same-ID Evidence with a different Root-content hash fails closed, including CRLF versus LF byte variants. Full-root closeout requires `subject_id` equal to the Root with null review/predecessor tips; correction closeout requires the complete review tip tuple from explicit chain artifacts.

With `artifact_kind: work-review`, the same tool consumes closed `review_input` Schema 1 and returns exact host-built Review bytes, `work_review_id`, `artifact_hash`, `review_input_hash`, authoritative fields, task-local validity, and optional handoff status. Without `artifact_kind`, `delivery-evidence` remains the default. The portable Manual surface remains exactly five tools. New full model-authored Reviews and raw Review recording do not establish authority.

An explicit compatibility MCP closeout outside the lifecycle still uses its delivery-report fence. Lifecycle-internal MCP use consumes `structuredContent` directly and emits no report or artifact dump to the user. Persisted Evidence must not appear in the completion message. When optional handoff persistence fails, exact Evidence retained by the current task needs no attachment; one bounded attachment remains compatible only for deliberate cross-task export. Both adapters invalidate recorded native or MCP closeout after later mutation, including child-agent mutation. Cursor permits the semantic delivery-closeout todo to complete pending the final native report, while the legacy MCP todo retains its pre-completion gate. Missing native Evidence produces one bounded recovery instruction, never an invented `de-*` report.

Cursor arms baseline capture and Stop recovery only when the current turn has both a conversation-bound Root and an explicit Manual implementation, correction, or review phase. Ordinary Ask-mode Shell/Task use, a Root from another conversation, or an older Root in the same conversation without a current Workflow turn must not create closeout-required state. An explicit closeout transport without a bound Root reports that no Root exists for the current task and emits no Evidence-recovery request.

Fresh review is a new read-only phase in the current task by default, not a new task requirement. When exact Evidence is missing, the reviewer gathers observations once and invokes the same closeout builder internally before emitting its Review. `phase: review-recovery` is only the single-continuation fallback. The Root-scoped chain retains the implementation baseline across later generations; without one, only the complete unambiguous current dirty set wholly within Root authority may produce provisional Evidence. Caller path hints never narrow or widen it, verified recovery observations are capped at `supported`, and a known failed Check stays failed. If recovery proves that baseline, Root binding, workspace identity, or path authority was irrecoverably lost after mutation, the native host records a short-lived protected receipt bound to the exact Root and current repository snapshot. Only a Review carrying that exact receipt may use the Schema-5 root-boundary variant. That Review has no Evidence and can authorize only a separately approved replan; portable/rootless or stale receipts authorize nothing.

Codex retains exact Schema-5 Root, generated Evidence, and emitted Review bytes in session/task state under the exact Root-content hash. A subsequent correction uses that task-local chain automatically; `workflow_artifact_context` may enrich it and `workflow_artifact_record` may transport it, but neither is required for the native happy path. Same-ID byte variants, different Root hashes, missing Source Review, stale predecessor Evidence, and conflicting correction lineage remain explicit fail-closed errors in the Stop response.

Codex recognizes each explicit Workflow skill only as an exact bare `$skill`, plugin-qualified `$geldmacher-workflow:skill`, or Markdown-link label in those forms. Host-generated `<hook_prompt>` continuations are never new human authority. Every genuine `UserPromptSubmit` first supersedes stale turn authority, then stages classification, selector, exact Root bytes, and hash; the candidate commits only after all pre-execution gates pass. A rejected candidate leaves no armed phase and therefore cannot impose later closeout, Evidence-recovery, or tool restrictions. Implementation inference remains limited to the documented direct English forms and the bounded observed German imperatives `Plan umsetzen`, `Setze den Plan um`, and `Setze diesen Plan um`; questions, negations, partial tokens, and foreign skill links remain inert.

Codex fail-closed delivery does not require endless task execution. A failed Stop may issue one continuation while `stop_hook_active` is false. If a Stop that would block again arrives with `stop_hook_active: true`, the adapter clears only the active turn, retains independently captured exact Root bytes and task artifacts as inert recovery context, records a bounded non-authoritative diagnostic, and returns terminal `continue: false` with visible `stopReason` and `systemMessage`. It emits no Evidence or delivery success. A valid closeout in that one continuation still completes normally; later ordinary prompts, read-only tools, and Stops remain unconstrained unless a new human-authorized phase passes its gates.

Shared adversarial lifecycle matrices must drive real kernel/Cursor/Codex/bundle adapter behavior for every applicable case. Enumerating case IDs or asserting a static expected outcome without invoking the host adapter is not proof. Before correction closeout, compare the normalized authorized dirty path set under Root authority with Evidence `changed_paths` and fail closed on omission or extras.

Unfinished-content detection matches explicit placeholder markup and uppercase `TBD`/`TODO`/`UNKNOWN` only; ordinary planning prose such as title-case Todo metadata must not fail closed.
