# Agents and native settings

Use the fixed built candidate and isolated fixtures under [the verifier](../SKILL.md). Capture the host version, accessible catalog, actual delegation schema, raw calls/results and separate identities outside the subject workspace. Native runs and controlled schema cases are separate evidence. Never supply expected phase judgments or the defect to subjects.

In both Codex and Cursor, exercise [Light and Dark](start.md) and [seeded correction](review.md) using at least two actually available models, plus supported reasoning/options. Start one task without a mapping: the subject proposes Plan/Implement/Review/Correct together and starts no phase until a trial-human answer. Preserve the proposal and pre-answer snapshot, then supply a complete selection. Start another task with a complete mapping: no redundant question. Include a shared Implement/Correct selection and different Review settings. Only applicable phases launch.

For each phase compare the selected mapping with actual native model/settings arguments or the chosen existing agent definition, including overrides and context/workspace restrictions. Record accepted/rejected invocation separately from host-confirmed execution. No metadata alone must not block a correct accepted invocation; never accept self-reported settings as confirmation. Known fallback/mismatch prevents dependent work. Every review and re-review has a fresh identity using Review's selection, while workspace files stay unchanged during Review. Phase agents return control without spawning subsequent Workflow phases. Inspect checkout routing and preserved unrelated files. Save original and post-correction raw evidence.

Inspect the first autonomous outcome report before any observer request for model evidence. It must itself distinguish selections, submitted native settings and unknown execution metadata. In resumed work, missing historical selections and submissions each stay unknown, separately from unconfirmed execution; today's mapping applies only to current/future roles, never those completed phases. Preserve later clarifications separately; an observer-repaired report cannot pass this check.

Default execution to unconfirmed. A confirmation needs a referenced host record reporting effective execution model/settings; accepted Task/spawn arguments, returned child IDs and agent assertions alone do not supply it. Keep phase judgments separate from this field. Inspect the two resumed cases separately: no backfilled Plan/Implement history in Dark, and no unsupported confirmed execution in Light.

Use controlled schema cases for unsupported fields, full-history/override incompatibility, configuration precedence, absent execution metadata, rejected calls and known mismatches. Supply an explicit tool schema/result as analysis input and ask what native call or next action is valid; do not claim these paper cases are live host execution or inject false runtime capabilities into a native trial. Verify settings are neither dropped nor encoded only in prompts, and rejected choices cannot silently fall back. For unknown catalog or unavailable delegation, use a context that really lacks that surface; otherwise mark the case unexecuted. A user-supplied ID may resolve an unknown catalog but cannot create unsupported tool fields.

Extend [continuity](continuity.md) with the same mapping: a mode switch and resume retain agents/settings and budget; an explicit Review change applies to the next fresh review, without rerunning a completed phase just to satisfy the new mapping. Handoffs retain selections, invocation evidence and the complete learning collection. Report any slot or depth limitation as an actual native capability gap. Cleanup owned workspaces only after raw transcript, calls, file snapshots and outcomes are saved in evidence.
