# Project subagent roles

Prepare an owned workspace with raw requirements for recurring independent inspection, an existing schema or analogous surface, and a deliberately faulty example. Preserve a baseline and keep the observer's expected finding outside the subject's context. Inspect the actual native host's project-role format and discovery/delegation capability; no global setup is included.

First commission setup inspection. Observe a bounded role proposal explaining its need, alternatives, project destination, inputs, output/evidence, read/write scope, inherited settings and closing native trial. A short one-shot command in a separate negative-selection case should not cause gratuitous role creation.

Accept the actual role proposal and commission its project-local implementation and trial. Inspect configuration against supported host behavior and existing entries. Launch a fresh native host session on that fixture if discovery requires it. Give a realistic task without the expected role or finding, then retain the host's actual role selection, child identity, instruction/config use, output and unchanged inspected files. Verify the deliberate defect is found through the intended role. Merely spawning a generic child or quoting the role file is insufficient.

Test supported project-role use in available Codex and Cursor hosts. For unavailable discovery or delegation, use an environment that actually lacks the capability and observe the missing proof and supported alternative. Do not ask a capable agent to pretend it lacks a tool. If that negative environment cannot be established, record the limitation instead of a pass.

Retain launch arguments, host/version, candidate digest, raw events and snapshots outside the workspace. Cleanup only owned role fixtures after evidence retention. Report configuration validity, saved-role discovery and delegated behavior separately; the portable package does not establish support in every third-party host.
