## Offer, subset and continuity

Prepare `bare`, inspect and probe it, then invoke only the candidate setup-workflow skill in a fresh native subject with the fixture workspace. Observe repository inspection before a reasoned package proposal: each entry needs findings, current coverage, benefit, destinations and closing proof. It must allow partial acceptance, revision and decline, avoid loading all nine entries without need, and leave files unchanged before implementation.

Respond to the actual proposal with an approved subset: behavior checks and project guidance; exclude CI and subagent roles. Include a concrete export verifier only when testing verifier cooperation, naming purpose, destination, zero/one/multiple-row coverage and a closing real-CLI trial. Commission implementation explicitly, preserving product, requirements and unrelated work. Inspect only the selected artifacts, run the new checks yourself and verify no second verifier consent. The setup choice must not select Engineering methods.

In an observer-owned copy, remove the first export row, run the subject's new check and confirm it fails for that defect. Never change the accepted product or weaken the oracle. Preserve before/after snapshots. Inspect the completed setup in a fresh maintenance subject and repeat the unchanged assignment; adequate coverage produces no redundant files or format migration.

Use separate `bare` subjects for declined and unanswered packages. Supply actual offers and decisions to fresh continuations; observe no repeated unchanged offer, implicit selection or edits. A materially changed task may justify a new specific offer. Use the maintenance recipe for `stale`, `regression` and `access`; observe selected method criteria without manufacturing additions to adequate coverage.

## Evaluation quality

Prepare an owned isolated project with a small source corpus, a support-answer quality requirement and human-reviewed good/bad calibration examples. Snapshot the raw inputs before the subject starts. Keep held-out outputs and expected judgments outside its workspace. Commission a local evaluator and instructions through an accepted evaluations scope; do not supply a required implementation or expected findings.

Inspect the objective, task-specific rubric, baseline, calibration and distinction between deterministic and judgment-based criteria. Run the produced route against separate good and unsupported-answer examples; verify a deliberately degraded answer is detected without changing the rubric. Record all observations, case counts and limits. This local evaluator trial does not establish unavailable live-provider answer quality. A subsequent model-generation subject must not receive calibration answers or the observer's hidden cases.
