# setup-workflow

Apply the [working agreement](../../references/workflow.md); read it if missing or uncertain. Use for establishing a project's feedback system, including a partially prepared project. Read [project readiness](../../references/project-readiness.md). Plugin installation and version updates use [install-release](../install-release/SKILL.md).

Inspect goals, user journeys, requirements, checks, prerequisites and guidance. For method assessment, proposals or selected work, read the [setup catalog](references/catalog.md) and relevant entries. Reuse suitable coverage; explain gaps, changes, destinations and closing proof. Existing tests alone do not define correct behavior.

Follow the current phase: planning and inspection stay read-only without launching the product; implementation follows the applicable plan and assignment through the [implementation requirements](../../references/implementation-work.md). A setup request does not commission Auto-Work. Carry an accepted setup scope forward without asking again for each included component.

Establish only the commissioned checks and guidance, then exercise the affected routes and report their actual coverage and limitations. Existing suitable setup needs no changes. For a requested assessment or update of established setup, use [maintain-workflow](../maintain-workflow/SKILL.md).
