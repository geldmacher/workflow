# Project skills

Use for a recurring procedure that benefits from discoverable, task-specific instructions. A simple command or short project note may suffice. Inspect existing skills and documented procedures first; extend the owning skill rather than creating a competing one.

## Make selection and execution reliable

Give the skill a precise purpose, audience and boundary. Its name and description should distinguish the real trigger from likely neighboring tasks. Use the host's supported metadata and existing project skill location. Keep the entry concise, load conditional detail through real relative links and ground helpers in actual project interfaces.

Write actionable decisions, expected results and likely failure cases rather than generic best-practice claims. Reuse maintained scripts for fragile repeated operations and document their arguments and effects. Preserve the workflow's phase and authority boundaries. A skill cannot grant permissions the host does not provide.

Verifier instructions are owned by [verification-work](../../verification-work/SKILL.md). Include its purpose, destination, coverage and closing trial in the accepted setup scope and follow its creation or maintenance guidance without duplicate approval. Do not automatically select the separate Engineering skill-authoring playbook merely because this entry is selected.

Possible artifacts are an existing skill update, one new project skill and its needed references/helpers. A recurring content-import procedure might describe input validation, a supported preview, the authorized import and resulting records; a one-line command needs no elaborate skill tree.

## Prove and maintain

Validate metadata and links, then try realistic matching and neighboring requests without giving the subject the expected selection. Observe actual reads, actions and artifacts. For an explicit-path execution trial, label it as execution rather than implicit discovery proof. Keep observer rubrics outside the subject context. Maintenance follows interface changes, missed or excessive activation and duplicated procedures; fix the demonstrated problem rather than adding general prohibitions.
