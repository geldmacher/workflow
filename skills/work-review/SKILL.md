Start fresh, repository-read-only. Read [protocol](../../references/artifact-protocol.md) and [review](../../references/review-contract.md); use the closed Manual schema.

Resolve task Root/predecessors when available; fresh tasks need attachment. Cache, hooks, IDs, transport, or ambiguity grant no authority. Run `validate-plan`. Missing or invalid formal binding does not prevent repository inspection: continue read-only as Shadow Review against the human plan text, without artifacts or Correct Work.

Inspect every objective, boundary, Check, and limit. Separate outcome from proof; the harness owns inspection.

When an applicable `.agents/skills/verify-*` exists, inspect its current contract and the project surface, then use its Drive only as a harness-owned recipe. Never edit it during Review. Root-relevant drift is a Finding; other drift is an Open Point. Raw Drive output is an observation only, verifier changes require fresh evidence, and `verified` still requires an exact protected attestation.

Supply the closed Schema-1 outcome (`achieved|correction-needed|open-points`), Findings, Open Points, repository observation, and Check observations. Set `presentation_locale: de` for German requests, else `en`. Partition each dirty path once as Root-subject or ambient; uncertainty is subject. Grades are `supported|partial|unavailable|failed`; author no IDs, hashes, attestations, or verified claims. `supported` needs a conclusive current-snapshot outcome; command presence, invocation, or a masked exit status is not enough. Every genuine limitation needs an Open Point with cause, evidence, impact, and one human question.

After inspection run local `build-review`. If it returns `check-observations-incomplete`, observe exactly the named missing Check IDs and retry internally. Continue only while the retry signature changes and progress is measurable; the same signature without progress becomes a concrete `no-progress` Open Point. Finding-free plus supported or verified required Checks is `achieved` with no action. Ambient paths are visible and non-blocking. Authority, environment, intent, or evidence limits become explicit Open Points.

Render `human_output` once; only decorate `presentation.next_action` (`correct`→**Correct Work**; otherwise use its named action). Append artifacts once, unchanged and unquoted, in builder order within one default-closed `<details>` titled `Technische Nachweise und Workflow-Artefakte`/`Technical evidence and Workflow artifacts`, below `Delivery Evidence · <label>` then `Work Review · <label>`. Shadow: none. Add nothing; never mutate.
