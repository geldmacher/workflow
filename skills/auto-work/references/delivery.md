# Delivery in Auto-Work

Resolve exactly which actions and destinations the human commissioned: commit, push, PR, merge, deployment, or publication. Permission for one action does not grant the others. Use the project's existing release instructions and native tools. Missing destinations or consequential release choices require a decision. No delivery assignment means finish at the repository result; do not create a pipeline, publish, or infer authority from the selected mode.

In Light, require human acceptance of the concrete reviewed result before delivery. Reuse that acceptance while the result remains unchanged. In Dark, require existing project mechanisms that enforce the necessary checks on the actual revision or artifact to be delivered. Inspect the configured required checks, their actual results, the artifact/revision binding, and the available release route; a test list, agent verdict, or green run for another revision is insufficient. The route must not allow the executing agent to bypass, replace, or weaken those gates under its current permissions. If enforcement or its protection cannot be established, delivery remains blocked with the specific gap. Do not silently fall back to Light or relax a gate.

Before each action, ensure review, checks, and applicable acceptance still cover the current candidate. A changed source, generated artifact, dependency, or relevant configuration requires reassessing affected evidence. The executor must not alter protected checks or expected outcomes to make its candidate pass. Pipeline creation or gate changes require their own concrete assignment; Auto-Work does not grant it.

Record the destination, candidate, invoked action, and observed result in the task. After an ambiguous failure or interruption, read the real destination state before retrying. Continue from confirmed completed steps; if the outcome cannot be established, stop with uncertainty rather than risk duplicate effects. Use existing project idempotency and recovery mechanisms where available. Do not perform an uncommissioned rollback.

Report repository verification, human acceptance where required, and delivery separately. Delivery failure leaves the commissioned assignment incomplete even if repository checks passed. A local simulation establishes only the tested gate and retry behavior, never production deployment or protection.
