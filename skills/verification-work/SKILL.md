# verification-work

Read the [working agreement](../../references/workflow.md) and [verification guidance](../../references/verification-work.md). Default to read-only `inspect`, without starting the product. Reuse suitable checks, harnesses, and verifiers. `create`, `maintain`, and explicit `maintain full` require the human's explicit acceptance of that work, an applicable plan, and matching implementation or correction assignment covering the destination and outcome. Reuse authorization already given; never infer it from an unaccepted suggestion.

For `create`, read only [creation](./references/create.md). For `maintain` or `maintain full`, read only [maintenance](./references/maintain.md). Planning may read the applicable reference to prepare the concrete proposal and handoff but cannot execute it. Create or modify only the authorized verifier surface. Default maintenance covers affected features; `maintain full` covers the agreed full map. Run the required trial at implementation close once product and verifier are ready together. Failed or unavailable necessary checks prevent a successful verification completion claim. Never change an oracle to hide a product regression.

Report paths, changes, exercised behavior, observations, and limitations. A changed verifier needs a fresh Review: separately commissioned in manual work or delegated within an expressly commissioned Auto-Work sequence. This action does not repair product code unless that work is independently within the current assignment.
