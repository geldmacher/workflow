# Workflow 5 validation boundaries

Repository validation covers Schema 5, Config/Policy 2, Protocol 5, deterministic Evidence, append-only indexed state, workspace-unattested recovery closeout, Lean/Full selection, active-Root resolution, Replan lineage, provisional acceptance, legacy read-only compatibility, Strategy chaining, authority, Dirty Baseline, task recipes, evidence calibration, model Pools, Verification Profiles, the inheritance and Schema-5 `CreatePlan` guards, MCP Roots, bundle parity, 10% context headroom, links, and the canonical release surface. Focused offline coverage gates require at least 80% lines and 70% branches for Root authority, the Schema-5 `CreatePlan` guard, Capability Receipts, release surface, Worker Adapter, and state/handoff indexes; generated bundles are excluded.

`release-surface.json` remains the canonical Cursor `runtime_paths` inventory used by Plugin hashing and isolated installed-copy startup. The target builder creates a separate Codex inventory and an independently validated Agent Plugins v1 package. Package verification requires complete copied surfaces without symlinks; every relative path resolves inside its selected plugin root. Codex leakage checks reject host-specific SDK/API-key identifiers and every Controller-only MCP tool name. Portable validation additionally checks the closed v1 manifests, nine immediate Agent Skills, contained references, environment placeholders, and the five-tool Manual MCP surface.

It does not by itself prove live Cursor model availability, hook enforcement, or actual inherited child-model identity. Following [Cursor's documented workaround for unenforced `subagentStart` denial](https://forum.cursor.com/t/subagentstart-hook-deny-is-not-enforced/166143/7), `preToolUse` is the primary Task override block. `subagentStart` compares the reported Child with the captured parent or a configured Manual approved candidate, while `subagentStop` and `postToolUse` distinguish a displayed denial from an executed and returned Child. Only Cursor can resolve and execute inheritance. Live smokes with two different Cursor-selected models must inspect the hook log and actual agent tree. A result returned despite Deny is recorded as `deny-not-enforced`; the result may still be used after separate fachliche verification, but the affected run is not exact-model-qualified. SDK enforcement, Marketplace installation, OS sandbox behavior, keychain access, real UI driving, and production dependency safety likewise require the separate certification runbook and an exact Capability Receipt Schema 4.

Repository tests verify provider-neutral parent switching, omitted/`inherit` requests, concrete override denial, equality and mismatch, missing and uncorrelated attestations, parallel/idempotent events, denial bypass observation, non-Workflow isolation, and incident privacy. Artifact Schema 5 and the authoritative `wp/de/wr/cp` chain remain unchanged.

Until every hard capability is positive, supervised remains Shadow Mode. Autonomous remains disabled per Qualification Key. Missing live proof is reported as unavailable; it is never promoted from repository tests or reviewer opinion.

`npm run release-check` is reproducible, offline, and inference-free. Registry audit, installed-copy/Marketplace smoke, and paid Cursor certification are separate gates. A fresh High/Critical production finding blocks certification until a minimal dependency fix or explicit hash-bound risk acceptance; an unavailable external check is never reported as passed.

Codex repository tests additionally prove host-authoritative path hydration in a pre-dirty checkout, exact task-local Root/Evidence/Review correction lineage without successful MCP record/context transport, classified Stop errors, and recoverable hash-bound Review quarantine. They do not update the installed plugin, reload an existing task, or mutate persistent handoff state. A local deployment, fresh Codex task, and any explicitly approved handoff maintenance remain separate gates; restart/reload alone never repairs an immutable cached conflict.

`npm run deploy:local -- --dry-run` is a checkout-neutral native deployment preview, not an installation. It copies only tracked and non-ignored untracked regular files into a disposable system-temporary snapshot, creates a snapshot-local dependency mirror from the checkout's physical `node_modules` (copy-on-write where supported) for build-time resolution, runs normal preparation there, and removes the snapshot on success or failure. `--full` also runs `release-check` in that snapshot. The preview may create temporary files but does not modify canonical generated outputs, Marketplace state, caches, or installed Cursor/Codex packages; a real deployment retains the canonical preparation and transactional replacement path.

Repository validation can prove the Cursor, Codex, and Agent Plugins bundles, eight Codex skills, nine portable Agent Skills, both five-tool Manual MCP surfaces, pure Hook decisions, migration behavior, and byte-preserving interoperability. It cannot prove that a personal marketplace accepted the copied native package, that the user trusted the current Hook hash, that a newly started Cursor or Codex task discovered every native component, that a compatible Agent Plugins client discovered and activated the portable skills and MCP server, or that any host enforced every live event. Native fresh-task and isolated compatible-client smokes remain separate; no new Codex or portable automation certification is implied because both non-Cursor targets expose Manual only.

Live smokes, paid model use, and registry or network access require separate explicit human approval and a stated cost limit before execution.
