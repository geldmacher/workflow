# Workflow 5 validation boundaries

Repository validation covers Schema 5, Config/Policy 2, Protocol 5, the deterministic Evidence builder, append-only handoff transport, recovery closeout, Lean/Full selection, shared active-Root resolution, linear Replan lineage, selectorless and explicit stateless Manual provisional acceptance, legacy read-only compatibility, Strategy hash chaining, scope authorization, Dirty Baseline, task recipes, evidence calibration, Decision Ledger, model Pool selection, Verification Profile lifecycle, the plugin-local parent-model inheritance hook contract, MCP/bundle parity, context budgets, links, and packaging.

It does not by itself prove live Cursor model availability, `subagentStart` enforcement, or actual inherited child-model identity. The hook can reject an explicit child-model request and require a reported parent model, but only Cursor can resolve and execute inheritance. Live smokes with two different Cursor-selected models must inspect the hook decision and agent tree; a displayed denial without proof that the child stopped remains host-unavailable. SDK enforcement, Marketplace installation, OS sandbox behavior, keychain access, real UI driving, and production dependency safety likewise require the separate certification runbook and an exact Capability Receipt Schema 3.

Until every hard capability is positive, supervised remains Shadow Mode. Autonomous remains disabled per Qualification Key. Missing live proof is reported as unavailable; it is never promoted from repository tests or reviewer opinion.
