# Workflow 5 validation boundaries

Repository validation covers Schema 5, Config/Policy 2, Protocol 5, deterministic Evidence, append-only indexed state, recovery closeout, Lean/Full selection, active-Root resolution, Replan lineage, provisional acceptance, legacy read-only compatibility, Strategy chaining, authority, Dirty Baseline, task recipes, evidence calibration, model Pools, Verification Profiles, the inheritance hook, MCP Roots, bundle parity, 10% context headroom, links, and the canonical release surface. Focused offline coverage gates require at least 80% lines and 70% branches for Root authority, Capability Receipts, release surface, Worker Adapter, and state/handoff indexes; generated bundles are excluded.

`release-surface.json` has one canonical `runtime_paths` inventory used by Plugin hashing and isolated installed-copy startup. Package verification requires that complete inventory plus the explicitly non-runtime `package_extras`; relative imports and `${CURSOR_PLUGIN_ROOT}` references must resolve inside the selected surface.

It does not by itself prove live Cursor model availability, `subagentStart` enforcement, or actual inherited child-model identity. The hook can reject an explicit child-model request and require a reported parent model, but only Cursor can resolve and execute inheritance. Live smokes with two different Cursor-selected models must inspect the hook decision and agent tree; a displayed denial without proof that the child stopped remains host-unavailable. SDK enforcement, Marketplace installation, OS sandbox behavior, keychain access, real UI driving, and production dependency safety likewise require the separate certification runbook and an exact Capability Receipt Schema 4.

Until every hard capability is positive, supervised remains Shadow Mode. Autonomous remains disabled per Qualification Key. Missing live proof is reported as unavailable; it is never promoted from repository tests or reviewer opinion.

`npm run release-check` is reproducible, offline, and inference-free. Registry audit, installed-copy/Marketplace smoke, and paid Cursor certification are separate gates. A fresh High/Critical production finding blocks certification until a minimal dependency fix or explicit hash-bound risk acceptance; an unavailable external check is never reported as passed.
